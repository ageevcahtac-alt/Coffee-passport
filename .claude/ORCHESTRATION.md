# Оркестрация: Claude + Codex

Подключено из корневого `CLAUDE.md` строкой `@.claude/ORCHESTRATION.md`.

## Роли
Главное правило: **кто пишет — тот исправляет.** Проверяющий код не правит, а только сообщает находки: файл, строка, проблема, как воспроизвести.

| Что | Пишет | Проверяет |
|---|---|---|
| Фичи, сложная логика, баги, весь UI | Claude (главная сессия) | Codex, режим `review` — каждый diff перед мержем |
| Миграции, CI, деплой-скрипты, шаблонные правки | Codex, режим `write` | Claude через субагента `code-reviewer` |

- В один момент пишет один агент. Пока работает Codex в `write`, Claude рабочее дерево не правит, и наоборот.
- **Мержит только Claude.** Условия: CI зелёный + ревью закрыто (все находки исправлены автором или отклонены с причиной).
- Кончился лимит у Claude — Codex дописывает по готовому плану из `.agents/tasks/<id>.md` в режиме `write`. Мерж — только после проверки Claude.
- Субагенты (`.claude/agents/`): `code-reviewer`, `qa-monitor`, `designer`. Вызывает главная сессия.

## Запуск Codex
```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/codex-run.ps1 <id> <prompt-file> -Mode review|write
```
- `review` → `--sandbox read-only`, `write` → `--sandbox workspace-write`. Первая строка промта — `MODE: review` или `MODE: write`.
- Промт — только файлом. Не передавать через `|`: PowerShell 5.1 перекодирует текст.
- В `.agents/runs/<id>/`: `prompt-N.md`, `codex-N.log`, `report-N.md`. Смотреть во втором терминале: `Get-Content -Wait -Tail 20 .agents/runs/<id>/codex-N.log`.
- Коды выхода: как у codex; `124` — таймаут (`CODEX_TIMEOUT`, по умолчанию 3600 с); `65` — codex вышел с 0, но отчёт пустой.
- Codex не помнит прошлый запуск: в каждый промт вкладывать план, прошлый отчёт и находки.

## Сервер
- Деплой — только `gh workflow run deploy` (и автоматически после merge в ветку прода). Красный `deploy` = прод не обновился или `/api/health` не ok → разбор как `fix-ci`.
- Диагностика — только `gh workflow run server-ops` (логи, порты, диск, контейнеры; только чтение). Вывод: `gh run view <id> --log`, хвостом.
- Локальный `ssh` к серверу не использовать: с этого компьютера сервер недоступен (VPN). Команды, меняющие сервер, — только новым шагом в `deploy` через PR с ревью.

## Ревью
1. Проверяющий выдаёт находки (`## REPORT mode: review` у Codex, `## AUDIT` у `code-reviewer`).
2. Автор **воспроизводит** каждую находку командой или тестом. Подтвердилась — исправляет сам. Не воспроизвелась или неверна — отклоняет и пишет причину в итог.
3. Новый раунд — по исправленному diff. **Максимум 2 раунда.** Дальше решает Claude: мержить, переписать или разбить задачу. Решение — с причиной в итоге.

## Цикл одной задачи (/task)
1. Прочитать задачу и только нужные файлы, большие — по диапазонам.
2. Решить самому. Пользователя спрашивать только если: 2+ равных пути с разным видимым поведением; нужен клик или доступ снаружи; платный сервис дороже $20/мес; необратимое действие с неясными последствиями. Секреты в чате не просить — только «создай файл X и положи туда».
3. Создать `.agents/tasks/<id>.md`: цель, автор (по таблице ролей), план (нумерованные пункты), критерии готовности (проверяемые командой), что НЕ трогать. `<id>` = `YYYYMMDD-HHMM-кратко` (латиницей).
4. Ветка — от `fix/pre-pilot-shortlist` (пока прод на ней, см. `CLAUDE.md`).
5. Автор пишет:
   - Claude — сам, с тестами;
   - Codex — промт `.agents/runs/<id>/prompt.next.md` (контекст, файлы, план, критерии, команды проверки, отчёт по `AGENTS.md`), запуск в `write`.
6. Ревью по разделу выше: diff Claude → Codex `review`; diff Codex → `code-reviewer`.
7. Задача трогает UI или маршруты → `qa-monitor`.
8. PR → зелёный CI → ревью закрыто → merge (делает Claude).
9. Закрыть: итог в `.agents/tasks/<id>.md`, строка в `.agents/REGISTRY.md`. Пользователю — только итог.

## Формат итога
```
## Итог <id>
Запланировано: 1.… 2.…
Написал: Claude | Codex — по пунктам, с файлами
Ревью: кто проверял, раундов N/2
  принято: <находка> → исправлено в <файл>
  отклонено: <находка> — причина
Проверки: команда → вывод (дословно, хвост)
Merge: PR #N, CI <ссылка/статус> | не мержено — почему
Результат: done | partial (что осталось и почему) | blocked (что нужно от пользователя)
```

## «Готово» только с доказательством
- Вывод проверок — дословно. Оценивать каждый пункт, а не общую галочку.
- Новая проверка показывается падающей на сломанном вводе.
- Не отдавать работу пользователю. Что можно сделать сейчас — делать сейчас.
- Логи — хвостом (`-Tail 60`), не целиком.

## Реестр и замена агентов
Файл `.agents/REGISTRY.md`. После каждой задачи — строка: дата, автор, проверяющий, задача, результат (ok / fix / fail), раундов ревью.
- Агент дал `fail` 2 раза подряд на задачах одного типа → переписать его промт (новая версия файла, причина — в «Замены») или создать узкого агента.
- Codex не сдал задачу в `write` за 2 раунда → разбить задачу иначе (по слоям или файлам), а не повторять промт.
- Нужна новая роль (SEO, перформанс, контент) → файл в `.claude/agents/` по образцу и строка в реестр.
