# 20261024-1600-shop-lot-path

Цель: после скана QR на `/passport/[lotId]` гость выбирает путь: «Я в кофейне — слепой каппинг» (как сейчас) или «Я в магазине — узнать о лоте» (сразу канонический лот, каппинг позже кнопкой). Оценка, сделанная после просмотра профиля, сохраняется с флагом `profile_seen_before_tasting`.
Автор: Codex (миграция 0034 + workflow наката миграций) → PR A; Claude (UI, флаг в данных, тесты) → PR B. Ревью: PR A — code-reviewer, PR B — Codex review.

## Схема (что выяснено)
- Оценка = строка `public.checkins`, пишет `lib/journey/store.ts` (`recordToRow` → insert). Кабинет кофейни: `fetchShopCheckins` — `select * … eq coffee_shop_id` (RLS по `profiles.cafe_id`, FK нет, `coffee_shops` в проде пуст). Кабинет обжарщика: `checkins_roaster_view` — явный список колонок, фильтр `profiles.roaster_id = c.roaster_id`.
- Новая колонка с default false не меняет ни RLS, ни view → кабинеты не трогаем.
- Накатить миграцию в прод сейчас нечем (только вручную по SSH, а SSH — только из Actions) → нужен workflow. Порядок expand: сначала колонка в проде, потом код, который её пишет (иначе insert в checkins падает на неизвестной колонке).
