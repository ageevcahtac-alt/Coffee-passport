# E2E-фундамент: агент e2e-runner + Playwright-инфраструктура + сценарии + CI

## Цель
Сквозное e2e-покрытие критичных пользовательских сценариев на Playwright и
заведённый агент `e2e-runner`, который их поддерживает. Base — `fix/pre-pilot-shortlist`
(прод), ветка `feat/e2e-foundation`.

## Автор
Claude (главная сессия). Ревью — Codex, режим `review`.

## План
1. Агент `.claude/agents/e2e-runner.md` по конвенции проекта; связь с `qa-monitor`
   описана в обоих файлах и в `.claude/ORCHESTRATION.md` (раздел «e2e-покрытие»).
2. Playwright: devDependency `@playwright/test`, `playwright.config.ts`
   (Chromium only, webServer = `next build && next start -p 3100`,
   retry 1 в CI, trace/скриншоты при падении), креды через `.env.e2e`
   (`.env.e2e.example` в репо, сам файл в .gitignore).
3. Сценарии в `e2e/`:
   a. гость → паспорт лота (`guest-passport.spec.ts`) — работает без бэкенда;
   b. вход энтузиаста → дегустация → чекбокс публикации по умолчанию выключен,
      opt-in публикует (`tasting-consent.spec.ts`, skip без E2E_ENTHUSIAST_*);
   c. карточка рецепта → «Сварил по этому рецепту» → «Ваш помол» сохраняется
      как конвертация помола (`recipe-brew-tasting.spec.ts`, рецепт сидится
      через localStorage — тот же источник данных, что у приложения);
   d. TDS вне диапазона прилипает к краю графика экстракции
      (`extraction-chart.spec.ts`);
   e. кабинет ростерии → «Процесс и происхождение» → блок «Процесс» с
      дисклеймером виден гостю (`roaster-process.spec.ts`; секция появится
      после влития PR #105 — на ветках без фичи тест честно пропускается).
4. CI: `.github/workflows/e2e.yml` — PR + workflow_dispatch, артефакты при
   падении (test-results/, playwright-report/), flaky-политика retry 1.
5. Проверки без регрессий: e2e (зелёный, со скипами по причинам), npm test,
   tsc, lint, build.
